# darktable 个人包安装与升级

先检查版本，再选择安装包。用户希望用 GitHub Actions 云端构建，避免在每台电脑安装编译环境。此 Skill 随仓库维护；具体命令、备份和各系统安装方法见 [references/package-install.md](references/package-install.md)，执行前读取。

## 版本与构建规则

- 默认目标是当前仓库 `origin` 的 `codex/dev`，不是上游最新版或 GitHub 默认分支。读取实际 remote、远端分支 SHA 和当前工作流，用户指定其他目标时采用该目标；不要借安装之机自动 rebase、提交或推送。
- 获取用户实际使用的程序路径及 `--version`。用 `scripts/check_version.py` 比较完整 Git 提交及祖先关系，不按版本字符串、时间或提交数量排序。无法识别、dirty 版本、分叉历史、远端查询失败都先核实，不当作版本落后。
- 本机与目标相同、本机较新，或之间仅改变 `.agents/`、Markdown 文档和已识别的 Skill/文档触发过滤：不重新构建，不默认重装或降级。同版本 AI 功能异常时先检查已有 AI 包、运行库、设置及模型，不能绕过版本规则重打包。
- 版本确实落后时，先检查本地已下载包和 GitHub Actions 成功产物。仓库、平台、构建 SHA、工作流与 AI 配置必须相符；版本脚本确认没有软件改变的祖先成功包可复用。已有包就下载、校验并安装；已有相关构建运行就等待，不另起一份。
- 只有版本确实落后、没有可复用包、没有相关构建进行中，才考虑云端构建。首次安装先复用已有包；没有本机版本也不能直接触发构建，应比较最新可用包与目标，证明包已落后再考虑。安装包过期、网络失败或不知道版本都不单独构成重建理由。
- 构建资格不是构建授权。按当前请求和仓库 AGENTS.md 判断提交、推送、重跑是否已获授权。当前工作流由 push 触发；不为触发构建制造空提交。已有同 SHA 运行可在需要且获授权时重跑对应平台 job；不假设存在 workflow_dispatch。

## 执行与结果

1. 只读检查本机、目标提交、已有包和运行状态，说明比较结果及下一步。需要身份登录时使用当前可用的 GitHub connector、CLI 或用户已登录的浏览器；不要要求本地编译环境。
2. 复用目标包，记录来源 run、完整 SHA、平台和下载校验。下载、构建日志及本机配置放在 Git 忽略的位置；不得将 token、安装包或照片库加入 Git。
3. 用户要求安装时，先准备完整安装包、安装位置和配置备份方案。实际升级前让 darktable 正常退出，备份真实配置目录和数据库；保留照片、XMP、AI 模型及旧版恢复材料。不要强制结束正在编辑或导入的应用。
4. 使用文件/命令接口安装，不接管鼠标键盘。保留实际 `--configdir` 和快捷方式参数，避免启动空照片库。安装后重新读取版本并核对 AI 编译支持及 ONNX Runtime；仅在实际模型推理完成后声称 AI 功能实测通过。
5. 报告版本判断、是否复用包、是否构建、安装/备份位置和实际验证范围。如果已是当前版本，明确说明无需重建；如果只是创建本 Skill，不顺便升级软件。

本目录的版本检查脚本只执行 Git 读取和程序 `--version`，不会构建、下载、关闭应用或安装。macOS 安装步骤提供命令指引，必须在实际 macOS 机器验证；Windows 验证不代表 macOS 验证完成。
